# IPT Velasco Personal Website

## Overview

`IPT_VelascoPersonalWebsite` is an ASP.NET Web Forms website intended to serve as a personal/portfolio site. It is a traditional, non-SDK-style .NET Framework project and currently contains the shared Web Forms application shell, startup configuration, static Bootstrap/jQuery assets, and template-oriented page references.

The application targets **.NET Framework 4.8.1** and uses C# code-behind files with ASPX, ASCX, and Master Page markup.

## Technology Stack

- **Runtime:** .NET Framework 4.8.1
- **Web framework:** ASP.NET Web Forms
- **Project format:** Legacy MSBuild project (`IPT_VelascoPersonalWebsite.csproj`), not SDK-style
- **CSS:** Bootstrap 5.2.3 plus `Content/Site.css`
- **JavaScript:** jQuery 3.7.0, Bootstrap JavaScript 5.2.3, Modernizr 2.8.3, and ASP.NET Web Forms scripts
- **Routing:** Microsoft ASP.NET FriendlyUrls 1.0.2
- **Asset bundling:** ASP.NET Web Optimization and Web Forms Optimization
- **JSON library:** Newtonsoft.Json 13.0.3 is referenced, although no application-specific JSON behavior is currently documented
- **Compiler provider:** Microsoft.CodeDom.Providers.DotNetCompilerPlatform 2.0.1
- **Development server:** IIS Express is enabled by the project settings, with HTTPS port 44377 configured

## Application Startup

1. ASP.NET loads `Global.asax` and invokes `Global.Application_Start`.
2. `RouteConfig.RegisterRoutes(RouteTable.Routes)` enables FriendlyUrls with permanent redirects.
3. `BundleConfig.RegisterBundles(BundleTable.Bundles)` registers the JavaScript and resource bundles.
4. Requests are rendered through the applicable ASPX page and shared master page.

`Authenticated.Master` provides the portfolio HTML document structure. It renders the current page title, loads the local Bootstrap stylesheet and bundle, provides anchor navigation for the portfolio sections, and renders the page-specific `ContentPlaceHolder1` placeholder. `Home.aspx` supplies the landing page content.

The Profile admin page at `/admin/profile` stores all public portfolio text in the singleton `Profile` entity. `Home.aspx` loads this record through the application profile service and HTML-encodes values before rendering them. The first request creates the default profile values when the database is available.

## Routing and Navigation

FriendlyUrls are enabled in `App_Start/RouteConfig.cs` with `RedirectMode.Permanent`. Navigation in `Site.Master` uses application-relative links:

- `/` - home route
- `/admin/profile` - edit public portfolio profile content
- `/admin/user-details?id={userId}` - read-only user account details
- `/About` - About route
- `/Contact` - Contact route

The project file contains references to `Default.aspx`, `About.aspx`, and `Contact.aspx` and their associated code-behind/designer files. If those files are absent from a particular checkout, treat the project file as a stale template reference and verify the working tree before implementing page-specific changes. Do not infer page behavior that is not present in source.

The admin audit-log page at `/admin/audit-logs` supports user search by username/email and filtering by Registration or Sign in. Results are loaded from `AuditLog` with the related `UserAccount`, ordered newest first, and limited to the most recent 200 matching records.

## Assets and Bundling

`BundleConfig` currently configures:

- `~/bundles/WebFormsJs` for Web Forms client-side functionality
- `~/bundles/MsAjaxJs` for Microsoft AJAX dependencies, in dependency order
- `~/bundles/modernizr` for the Modernizr development script
- A jQuery `ScriptResourceDefinition` used by ASP.NET `ScriptManager`

The master page references the CSS bundle at `~/Content/css` and renders Bootstrap JavaScript through `~/Scripts/bootstrap.js`. When changing bundles, preserve dependency order and check both debug and release behavior.

## Configuration and Dependencies

`Web.config` targets .NET Framework 4.8.1 for both compilation and `httpRuntime`. It registers the Web Optimization Web Forms controls and includes binding redirects for Antlr, Microsoft.Web.Infrastructure, Newtonsoft.Json, and WebGrease. CodeDOM uses the Microsoft.CodeDom provider package.

NuGet dependencies are managed through `packages.config`. The project expects packages to be restored before building. The `packages/` directory is a local dependency output/cache and should not be treated as application source.

## Build and Run

### Visual Studio

1. Open `IPT_VelascoPersonalWebsite.slnx` in Visual Studio.
2. Restore NuGet packages if prompted.
3. Select the `IPT_VelascoPersonalWebsite` project as the startup project.
4. Run with IIS Express. The project is configured for HTTPS port `44377`.

### Command line

Build the project with MSBuild from a Visual Studio Developer PowerShell, for example:

```powershell
msbuild .\IPT_VelascoPersonalWebsite.csproj /t:Build /p:Configuration=Debug
```

A successful build verifies compilation and project-file consistency, but it does not replace a browser smoke test of the Web Forms application.

## Portfolio Landing Page

The authenticated landing page is `Home.aspx` at the project root and uses `Authenticated.Master`. It contains:

- Personal information with Gmail, LinkedIn, and GitHub links using local SVG assets.
- Educational attainment: Senior High School Graduate (2022–2024) and Information Technology (2024–Present).
- Hobbies and interests: studying, listening to music, and watching movies.
- Skill placeholders for future content and icons.
- A Get in touch call to action and footer contact/social links.

Profile names and contact URLs are intentionally placeholders and should be replaced with the owner’s actual information.

The page uses Bootstrap components and utility classes with only minimal additions in `Content/Site.css`. The new master page does not implement authentication itself; authentication and access control remain outside the scope of the landing-page UI.

## Current Scope and Limitations

- No database, API layer, or application service layer is currently present in the documented source structure.
- The current login and registration code-behind files do not contain authentication persistence or access-control logic; the portfolio page should be connected to the application’s authentication flow when that feature is implemented.
- No automated test project or test suite is present.
- The site still contains template branding such as `Application name` and `My ASP.NET Application`; these are presentation placeholders, not configured site metadata.
- The project file includes template page entries that should be checked against the actual checkout before page work is started.
- `Web.config` has `compilation debug="true"`; production deployments should use the appropriate release transform and deployment configuration.

## Change Guidance

Prefer small, targeted changes that follow the existing Web Forms patterns. For a new page, add the ASPX markup, code-behind, designer file, and corresponding project entries consistently. Shared layout changes generally belong in `Site.Master`; startup changes belong in `Global.asax.cs`, `App_Start/RouteConfig.cs`, or `App_Start/BundleConfig.cs` as appropriate.

Because this is a .NET Framework 4.8.1 application, do not introduce ASP.NET Core middleware, minimal hosting, SDK-style project assumptions, or APIs unavailable on the target framework without an explicit migration plan.
